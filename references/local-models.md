# 本地模型适配指南

## 1. 上下文预算

| 上下文 | 加载内容 | 教学形态 |
|---|---|---|
| < 8k | 只读 `minimal-core.md` | 一问一答，不做多轮主题图 |
| 8–16k | 只读 SKILL.md | 诊断 → 讲一点 → 用户说 → 反馈 → 记录 |
| 16–32k | SKILL.md + 一个模式文件 | 完整循环 |
| > 32k | 再加一个 pedagogy 文件 | 完整循环 + 精读 |
| > 64k | 可加载全部引用 | 仍禁止一次加载多个模式 |

原则：**宁可少加载，也不要让关键规则被挤出上下文**。

## 2. 提示风格

- 短句、祈使句；一条指令只做一件事。
- 列表不超过两层；避免长表格和复杂嵌套。
- 关键规则在 SKILL.md 和模式文件里各说一遍（重复是特性，不是冗余）。
- 少用抽象名词，多用动作："先问一个问题"而不是"进行诊断性交互"。
- 中文模型对中英混排较敏感；术语首次出现时给中英对照。

## 3. 工具调用

- 假设工具调用不稳定：每个调用只做一件事，参数尽量少。
- 调用失败一次就降级，不反复重试；不要让用户看着模型空转。
- 不要依赖并行工具调用；顺序执行。
- 不要假设模型能可靠生成 JSON；结构化状态交给脚本。
- 脚本输出保持短小（默认 top 5、摘要 200 字内），避免撑爆上下文。

## 4. 生成参数建议

| 场景 | temperature | 说明 |
|---|---|---|
| 讲解、诊断、评分 | 0.2–0.4 | 稳定、少发挥 |
| 类比、头脑风暴 | 0.6–0.8 | 允许发散 |
| 精读引用 | 0.1–0.3 | 尽量贴原文 |

- 评分和引用不要用高温度。
- 不要依赖 `stop` 序列做格式控制；用明确的输出模板。

## 5. 常见失败与修正

| 失败 | 修正 |
|---|---|
| 一次讲太多 | 在模式文件里写死"180 字后必须提问" |
| 忘记状态 | 每轮开头先读 `status`；把状态摘要放在系统提示末尾 |
| 编造引用 | 强制 `[S:] / [M] / [?]` 三选一；无来源必须标 `[M]` |
| 把摘要当精读 | 精读模式第一条规则写"不许通读后总结" |
| 评分虚高 | 给 0/1/2/3 的具体锚点，要求附证据 |
| 苏格拉底上瘾 | 用户说"直接告诉我"时，规则优先于模式 |
| 忽略中文 | 配置 `language: auto`；术语中英对照 |
| 长上下文退化 | 每 6–8 轮做一次 150 字滚动摘要，旧内容可丢 |

## 6. 模型规模参考

- **7B–8B**：只跑最小循环；不要主题图、不要多文件精读；一次一个概念。
- **14B**：可跑完整循环；精读只做单节；状态依赖脚本。
- **32B+**：可跑系统学习和论文精读；仍建议一次只加载一个模式。
- **MoE / 长上下文模型**：可放宽上下文，但不要放宽"学习者产出"和"来源诚实"。

## 7. 离线部署检查

启动时运行 `edu.py doctor`，确认：

- Python 版本 ≥ 3.8
- 工作区可写
- 是否有 `pdftotext` 或 `pypdf`（没有就只能读 txt/md/epub）
- `allow_network` 为 false
- 磁盘剩余空间足够存放 corpus

任何一项不满足，按降级矩阵处理，不要中断教学。
