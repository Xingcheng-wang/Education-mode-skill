# 部署假设与能力边界

## 1. 目标模型

本 skill 按以下假设设计，不再为小模型或弱模型做结构性妥协：

| 能力 | 假设 |
|---|---|
| 上下文 | 1,000,000 tokens |
| 指令遵循 | 可靠，能执行多步规则 |
| 工具调用 | 可靠，能读写文件、执行脚本、检索网页 |
| 多模态 | **不支持**（非多模态） |
| 推理 | 标准大模型水平 |

如果实际部署的模型低于上述假设，由部署方负责降级；本 skill 不把"小模型"作为默认设计前提。

### 1M 上下文能装多少

- 英文：约 70 万–80 万词（1 token ≈ 0.75 word）。
- 中文：约 50 万–70 万汉字（因 tokenizer 而异）。
- 一篇论文通常 5k–15k tokens；一本 300 页的书通常 15 万–30 万 tokens。多数情况下可以整篇/整本读入。

### 上下文不是记忆

1M 上下文只解决"单次会话能看多少"，不解决"跨会话记住谁"。因此：

- 学习状态、误解、复习排程仍写入 `learner/`、`sessions/`、`notes/`；
- 这不是对小模型的妥协，而是为了持久化、可审计、可迁移；
- 新会话先读状态，而不是依赖上一次的上下文。

## 2. 检索模式

`config.json` 的 `retrieval_mode` 决定本次会话是否允许联网检索：

| 值 | 含义 | 联网 |
|---|---|---|
| `local` | 只用本地 corpus 和模型知识 | 禁止 |
| `web` | 允许公开网页检索 | 允许 |
| `ask` | 每次会话询问一次 | 由用户决定 |
| `auto` | 有网页工具则 `web`，否则 `local` | 视工具而定 |

默认 `ask`。生产内网建议固定 `local`；需要补查文献时再由用户临时切换。

`auto` 不主动 ping 网络，而是以宿主是否提供网页检索工具为准；首次检索失败则回退 `local`。

切换命令：

```bash
python <SKILL_DIR>/scripts/edu.py config --home <EDU_HOME> --set retrieval_mode=local
python <SKILL_DIR>/scripts/edu.py config --home <EDU_HOME> --set retrieval_mode=web
```

## 3. 能力边界

### 能做的

- 读整篇论文、整本书、多个来源并做对照；
- 建立全局结构图、跨章节综合分析；
- 调用本地脚本做索引、检索、排程、记录；
- 在允许时检索公开网页并缓存；
- 生成结构化笔记、练习、评测。

### 不能做的

- 看图、表格截图、扫描页、视频（非多模态）；
- 在没有网页工具时联网；
- 在 `local` 模式下检索网页；
- 保证网页内容的真实性与时效性（必须标注来源与日期）；
- 代替用户完成真实操作或提供高风险专业结论（医学、法律、安全操作需提示核实）。

### 非多模态的处理

遇到图像、图表、扫描页：

1. 明确说"我看不到这张图"；
2. 请用户用文字描述关键信息，或提供图注/数据表；
3. 如果有离线 OCR 结果，读 OCR 文本并标注；
4. 不要根据上下文猜测图中内容，也不要把图注当成完整信息。

## 4. 隐私

- 学习记录、画像、误解库、会话内容全部留在本机 `<EDU_HOME>`。
- `web` 模式下，搜索查询只包含主题关键词；不得包含姓名、画像、会话摘要、代码、文件路径或其他个人数据。
- 网页缓存保存在 `corpus/<id>/`，不自动上传。
- 共享机器应限制 `~/.edu` 的目录权限。

## 5. 部署检查

```bash
python <SKILL_DIR>/scripts/edu.py doctor --home <EDU_HOME>
python <SKILL_DIR>/scripts/edu.py validate --home <EDU_HOME>
```

确认：

- `retrieval_mode` 与部署环境一致；
- `context_window` 与实际模型一致（默认 1000000）；
- `multimodal` 为 false；
- 本地 corpus 可读写；
- PDF 解析工具可用，或已有 txt/md 版本；
- 学习工作区不在共享只读目录。
