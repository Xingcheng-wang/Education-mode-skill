# Spark 模式（想法捕获与分诊）

**适用**：用户突然有一个想法、设计、假设或项目念头，可能是原创的，也可能别人已经做过。

Spark 不是第五种“内容学习模式”，而是一个 **triage 层**：它决定这个念头该 park、该读、该试、该做成项目，还是该拆成几个好奇心问题。

## 1. 与好奇心模式的边界

| 维度 | 好奇心模式 | Spark 模式 |
|---|---|---|
| 触发 | “为什么/是什么/解释一下” | “我有个想法/为什么不做 X/这是不是有人做过/突然想到” |
| 对象 | 一个关于世界的问题 | 一个候选主张、设计、假设或项目 |
| 目标 | 建立正确的心理模型 | 判断价值、新颖性、可行性，决定下一步 |
| 输出 | 解释、机制、边界、一个钩子 | spark note、先行工作、最危险假设、最小验证 |
| 先行工作 | 需要时才查 | **必须查**，限时 30–60 分钟 |
| 是否要下一步 | 可选 | 必须（park 也算下一步） |
| 生命周期 | 通常一次会话 | `seed → exploring → parked / project` |
| 成功标准 | “我懂了” | “我知道该不该继续、下一步最小动作是什么” |

判断口诀：

- 如果“给我一个完美解释，我就满意地结束” → 好奇心。
- 如果需要“有没有人做过/值不值得投入” → Spark。
- 如果有一个可以被验证、被反驳的主张 → Spark。

边界不清时只问一句：

> “你是想弄懂这个领域，还是想判断这个想法值不值得做？”

## 2. 流程

### 2.1 Capture

一句话写清：

- 主张：X 可以通过 Y 做到 Z。
- 为什么现在：什么变化让这件事变得可能/重要。
- 为什么是我：你手里有什么独特条件。
- 类型：`question` / `hypothesis` / `design` / `project`。

先抓住，不评判。

### 2.2 Prior-art triage

限时 30–60 分钟，不做完整文献综述：

- 本地 corpus + 网页；
- 找 5–10 个直接/相邻工作；
- 每个标注关系：
  - `solved`：已经有人做了同样的事；
  - `adjacent`：相邻，但层/范围/约束不同；
  - `open`：这个具体问题还没被解决；
  - `different`：同名但不同问题。
- 记录“如果我要做，差异点在哪”。

命令：

```bash
edu.py spark --home <EDU_HOME> --action prior-art --id s0001 \
  --source "W3C AI Agent Memory Interop CG" --relation adjacent --note "标准化讨论"
```

### 2.3 Decompose

把大想法拆成：

- 子问题（可以分别用好奇心/精读/系统学习解决）；
- 最危险的假设（通常不是技术，而是“别人为什么要用”）；
- 最小验证（1–2 天能做完的测试，而不是完整产品）。

### 2.4 Decide

四选一：

- `park`：记下来，暂时不做。Park 是成功。
- `read`：精读 2–3 个最相关的工作。
- `test`：做一个最小验证/原型。
- `project`：验证通过，转成项目型滚动计划。

### 2.5 Record

写入 `sparks/<id>.md` 和 `sparks/index.json`：

- 主张、为什么现在、为什么是我；
- 类型、状态、下一步；
- 先行工作；
- 最危险假设；
- 最小验证。

### 2.6 Route

| 路由 | 去哪 |
|---|---|
| `curiosity` | 先弄懂一个子问题 |
| `deep-read` | 精读先行工作/协议论文 |
| `systematic` | 把子问题加进问题地图 |
| `skill-drill` | 做最小原型/转换器 |
| `project` | 转成项目型 Now / Next / Later |

```bash
edu.py spark --home <EDU_HOME> --action route --id s0001 --to deep-read
```

## 3. 状态

| 状态 | 含义 |
|---|---|
| `seed` | 刚捕获，还没 triage |
| `exploring` | 正在读/问/试 |
| `parked` | 有意搁置；不是失败 |
| `project` | 已决定投入，转项目计划 |

没有提醒、没有排名、没有“你还有 N 个想法没处理”。只有用户问起时才列出。

## 4. 例子：统一 LLM 记忆格式

- 主张：用一套格式/协议统一 LLM 记忆的组织、存储与迁移。
- 先行工作：W3C AI Agent Memory Interop CG、Universal Memory Protocol、Portable Agent Memory、Text2Mem、memorywire 等。
- 最危险的假设：厂商/框架有动机采用统一格式。
- 最小验证：选两个记忆系统，做导出→导入→再导出，测语义损失、provenance 保留、删除传播。
- 结论可能是：大方向已有人做，但“一致性测试/学习记录 profile/权限与遗忘层”仍有缝隙。
- 状态：先从 `seed` 到 `exploring`，读完 2–3 篇再决定 `park` / `test` / `project`。

## 5. 无文件工具时

输出一段 Spark Note（主张/类型/先行工作/最危险假设/最小验证/状态/下一步），让用户自己保存。
不要假装写入了 `sparks/`，也不要在后续会话里假装记得它。

## 6. 规则

- Spark 不是承诺；park 不叫失败。
- 先杀，再养：先用低成本检索和最小验证，不要一开始写大计划。
- 不做 novelty 断言，除非做过检索并引用来源。
- 不把“想法”直接变成“项目”；先过 triage。
- 不制造 idea backlog 债务；不提醒、不排名、不显示未处理数量。
- 允许降级：Spark 可以拆回几个好奇心问题。
- 允许升级：好奇心可以升级为 Spark。
- 所有外部资料标注 `[S:]` / `[W:]` / `[M]` / `[?]`。
