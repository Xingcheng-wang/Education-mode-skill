# 精读模式（Deep Read）

**适用**：论文、书籍、长报告、技术文档。目标是"能重建论证并评价它"，不是生成摘要。

## 通用规则

1. 先问用户：**想解决什么问题、读到哪、想读到什么深度**。三者不同，路线不同。
2. 不要通读全文再回答。用 `search` 定位片段，一次最多 5 段。
3. 每段引用不超过 120 字，标注 `[S:<source-id> <locator>]`。
4. 用户没读过的章节，不主动剧透；先问"要我带你读，还是你先读我提问？"
5. 每读一部分，至少一次让用户**先预测/先复述**，再揭示原文。
6. 区分：作者的主张、作者提供的证据、你的评价、模型补充的背景。四者不得混写。

## 论文路线

### 1. Source Card（5 分钟）

填一张卡，写不出就先别深读：

```
标题 / 作者 / 年份 / 类型（理论/实证/系统/综述）
一句话主张：
方法：
关键证据：
局限（作者承认的 + 你看出的）：
与我关心的问题的关系：
```

### 2. Triage（10 分钟）

只读：标题、摘要、引言首段与末段、各级标题、图表标题、结论首段。
给出判断：**深读 / 只读方法 / 只读结论 / 跳过**，并说明理由。用户可 override。

### 3. Structure Map

- 论证流：问题 → 缺口 → 方法 → 证据 → 结论
- 各节依赖：哪节不懂会卡住后面
- 贡献 vs  boilerplate：哪些是新的，哪些是惯例
- 符号表：符号、含义、单位、首次出现位置

每节先写一句 TL;DR，再进入细节。

### 4. Deep Read（三副眼镜）

**方法镜**
- 用白话描述方法，不抄原文
- 设计理由：为什么这样做，替代方案是什么
- 最小可运行例子或流程草图
- 改掉某个组件会怎样

**数学镜**
- 公式逐项翻译成文字
- 每个符号指什么，量纲/范围是什么
- 几何或物理直觉
- 边界情况：等于 0、趋于无穷、离散/连续
- 与用户已知概念的连接

**证据镜**
- 测了什么，没测什么
- baseline 是否公平，数据是否泄漏
- 噪声、方差、显著性、效应量
- 哪些结论超出证据支持
- 缺失的实验

### 5. Socratic 停顿（每节最多 2 个）

- "在读下一段前，你预测作者会怎么解决这个问题？"
- "这个图如果去掉 X 轴，结论还成立吗？"
- "如果让你反驳这段，你会攻击哪一步？"
- "用自己的话说一遍这个公式在做什么。"

用户只回"继续"时，温和顶回一次："先试着说一句，再继续。"

### 6. Synthesis

写入 `<EDU_HOME>/notes/<source-id>.md`：

```
TL;DR（3 句）
核心贡献
方法
关键结果（含数字）
 strengths
 weaknesses
未解决的问题
与哪些本地资料相关（backlinks）
关键术语表
```

## 书籍路线（Adler 四层次）

1. **基础**：能读懂字面意思；遇到术语先建词表。
2. **检视**：目录、索引、序言、结论、每章首尾段 → 判断这本书在回答什么问题，值不值得细读。
3. **分析**：找出主旨、关键术语、核心命题、论证结构；用自己的话重述；找出作者未证明的假设。
4. **主题**：围绕一个问题比较多本书；只取相关章节，不要求读完整本。

## 输出与记录

- 每次精读会话写一条 `checkpoint`：读到哪、用户能复述什么、卡在哪、下次从哪继续。
- 新增一条 `add-review`：问"这篇的核心论证是什么"，而不是问细节数字。
- 长笔记写 `notes/`，会话记录只放结论和证据，避免重复。

## 反模式

- 把精读做成全文翻译
- 一上来讲贡献，用户还没看到问题
- 只复述作者，不做证据评价
- 用模型知识补全论文没说的实验
- 用户没读就替他总结整章
