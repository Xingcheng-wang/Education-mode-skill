# 精读模式（Deep Read）

**适用**：论文、书籍、长报告、技术文档。目标是"能重建论证并评价它"，不是生成摘要。

阅读是与作者对话，不是信息提取。允许不同意、反复读、跳读、只读感兴趣的部分；不追求"读完"或"笔记字数"。

## 1. 先定三件事

问用户：

1. 想解决什么问题？（不是"想读懂"，而是"读完后要做什么/判断什么"）
2. 读到哪、想读多深？（速览 / 方法 / 全文精读 / 主题比较）
3. 材料在哪？（本地 corpus / 用户粘贴 / 允许联网查找）

再按 `retrieval_mode` 取材：

- `local`：只用本地 corpus 和模型知识；缺资料就说明缺口。
- `web`：可以补查公开论文、官方文档、作者主页；查询只含主题/标题关键词，不发送用户画像；结果缓存并引用。
- `ask`：先问一次是否允许联网。

## 2. 选择阅读策略

目标模型有 1M 上下文，不必默认"只读片段"。

| 材料规模 | 策略 |
|---|---|
| 单篇论文 / 单章 / ≤约 20 万汉字 | `read` 全文，先建全局结构图，再逐节深读 |
| 一本书 / 长篇报告（约 20 万–60 万汉字） | `outline` + `read` 分段，维护全局章节地图和术语表 |
| 超过约 60 万汉字 / 多本书 | `outline` + `search` 定位 + 分段 `read`；不要一次性硬塞 |

命令：

```bash
python <SKILL_DIR>/scripts/edu.py outline --home <EDU_HOME> --source <id>
python <SKILL_DIR>/scripts/edu.py read --home <EDU_HOME> --source <id> --max-chars 400000
python <SKILL_DIR>/scripts/edu.py search --home <EDU_HOME> --query "..." --source <id> --top 5
```

无论哪种策略，都要保留 locator，引用时写清页码/章节/行号。

## 3. 论文路线

### 3.1 Source Card（5 分钟）

```
标题 / 作者 / 年份 / 类型（理论/实证/系统/综述）
一句话主张：
方法：
关键证据：
局限（作者承认的 + 你看出的）：
与我关心的问题的关系：
```

这张卡是用来帮你抓住论证的，不是准入门槛；写不出来也可以直接读，遇到问题再回来补。

### 3.2 Triage（10 分钟）

只读：标题、摘要、引言首段与末段、各级标题、图表标题、结论首段。

给出判断：**现在深读 / 只读方法 / 只读结论 / 先放着**，并说明理由。用户可 override。
Triage 是建议，不是门槛；用户想读哪里就读哪里。

### 3.3 Structure Map

- 论证流：问题 → 缺口 → 方法 → 证据 → 结论
- 各节依赖：哪节不懂会卡住后面
- 贡献 vs boilerplate：哪些是新的，哪些是惯例
- 符号表：符号、含义、单位、首次出现位置

每节先写一句 TL;DR，再进入细节。

### 3.4 Deep Read（三副眼镜）

**方法镜**
- 用白话描述方法，不抄原文
- 设计理由：为什么这样做，替代方案是什么
- 最小可运行例子或流程草图
- 改掉某个组件会怎样

**数学镜**
- 公式逐项翻译成文字
- 每个符号指什么，量纲/范围是什么
- 几何或物理直觉
- 边界情况：等于 0、趋于无穷、离散/连续
- 与用户已知概念的连接

**证据镜**
- 测了什么，没测什么
- baseline 是否公平，数据是否泄漏
- 噪声、方差、显著性、效应量
- 哪些结论超出证据支持
- 缺失的实验

### 3.5 Socratic 停顿（每节最多 2 个）

- "在读下一段前，你预测作者会怎么解决这个问题？"
- "这个图如果去掉 X 轴，结论还成立吗？"
- "如果让你反驳这段，你会攻击哪一步？"
- "用自己的话说一遍这个公式在做什么。"

用户只回"继续"时，尊重；可以在本节结束时留一个可选问题，不要强行把阅读变成问答。
提问是为了加深理解，不是为了证明用户在认真读。

### 3.6 Synthesis（可选）

如果用户想留下笔记，写入 `<EDU_HOME>/notes/<source-id>.md`；不想写就不写，不把阅读变成笔记生产。不是摘要，而是"我读到了什么、我怎么看"：

```
作者在回答什么问题
核心主张与论证
关键证据（含数字）
我同意的地方 / 我不同意的地方 / 我还没弄明白的地方
它改变了我对什么问题的看法
与哪些本地/网页资料相关（backlinks）
关键术语表
```

## 4. 书籍路线（Adler 四层次）

1. **基础**：能读懂字面意思；遇到术语先建词表。
2. **检视**：目录、索引、序言、结论、每章首尾段 → 判断这本书在回答什么问题，值不值得细读。
3. **分析**：找出主旨、关键术语、核心命题、论证结构；用自己的话重述；找出作者未证明的假设。
4. **主题**：围绕一个问题比较多本书；只取相关章节，不要求读完整本。

### 1M 上下文下的整本书读法

1. **先看目录与索引**，建立章节地图和术语表，不要从第一页直接读到最后。
2. **读全文**（或分段读），边读边维护：
   - 章节 → 核心问题 → 主张 → 证据
   - 关键术语的首次定义与后续变化
   - 前后矛盾或重复
3. **每章结束**可以邀请用户用一句话复述；不想说就继续读，不要等整本读完再"考试"。
4. **跨章综合**：哪些主张依赖其他章节？哪些例子反复出现？作者的立场有没有变化？
5. **主题比较**：把多本书的目录和关键章节并排，按问题组织，而不是按书组织。
6. **允许不读完**：一本书的价值不取决于是否翻到最后一页。

## 5. 引用与来源

| 来源 | 标注 |
|---|---|
| 本地资料 | `[S:<id> <locator>]`，如 `[S:paper-x p.7]` |
| 网页 | `[W:<id> <url> accessed YYYY-MM-DD]` |
| 模型知识 | `[M]` |
| 不确定 | `[?]` |

- 每段引用不超过 120 字。
- 页码/章节来自 `ingest` 输出的 locator，不要自己估算。
- 网页资料必须缓存后再引用；缓存方法见 `references/retrieval.md`。
- 找不到原文时，明确说"没有找到"，不要用模型知识补写成论文原文。

## 6. 非多模态边界

不能看图、表格截图、扫描页、视频。遇到图像：

1. 明确说"我看不到这张图"；
2. 请用户描述关键信息，或提供图注/数据表/OCR 文本；
3. 图注只能作为部分证据，并标注"来自图注，未见原图"；
4. 不要根据上下文猜测图中的曲线、数值或结构。

## 7. 输出与记录（可选）

- 只有用户同意记录时，才写一条 `checkpoint`；默认 `outline` 只记概要，不写理解状态。
- `add-review` 只在用户说"帮我记一下这个问题"时加。
- 长笔记写 `notes/`；会话记录默认只放概要，原话只在 `verbatim` 同意时保存。
- 多来源对照时，在笔记里维护 backlinks 和"冲突/一致"标注。
- 不记录"读了多少页/多少字"，不用页数衡量收获。

## 8. 收尾（三行，可选）

```
这一轮学到了什么：<一个具体的理解或判断>
这一轮还想探索什么：<一个作者没回答、或你想反驳的问题>
下一轮想试什么：<一个可以读/写/做的下一步>
```

用户不想总结就直接结束，不追问。


## 9. 反模式

- 把精读做成全文翻译或摘要
- 一上来讲贡献，用户还没看到问题
- 只复述作者，不做证据评价
- 用模型知识补全论文没说的实验
- 用户没读就替他总结整章
- 把整本书无结构地塞进上下文再"总结"
- 假装看过图、表格截图或扫描页
- 引用没有 locator / URL / 访问日期
- 用"读完/读了多少页/笔记多少字"衡量阅读
- 把阅读变成必须通过的问答
- 用户想继续读却强行停下来考试
- 把作者的话当成不可质疑的结论
- 强制写 source card 或 synthesis 才能继续
- 未经同意保存原文长段或阅读记录
