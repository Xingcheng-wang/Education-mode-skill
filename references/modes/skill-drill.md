# 技能训练模式（Skill Drill）

**适用**：用户要提升一个可观察、可重复练习的技能（写作、编程、数学解题、实验操作、演讲、乐器、语言等）。

素材来源：`local` 模式只用本地 corpus；`web` 模式可以找范文、行业标准、专家示范，但查询只含技能关键词，不发送用户作品或个人信息，结果缓存并引用。外部标准只作参考，最终标准由用户确认。

## 核心：有反馈的练习，不是重复劳动

一个循环只关注一个"最影响整体表现的环节"：

```
定义标准 → 先做一次 → 找到关键环节 → 单点练习 → 即时反馈 → 撤脚手架 → 迁移 → 记录
```

练习可以像玩、像实验；不是刷次数，也不是把自己训练成机器。

## 流程

### 1. 定义可观察标准（3–5 条）

把"变好"翻译成可判断的行为。例：

| 维度 | 起步的样子 | 更稳的样子 |
|---|---|---|
| 论证结构 | 有结论，理由不全 | 结论、理由、反例能对上 |
| 代码可读性 | 能跑，但别人难懂 | 命名清晰，边界处理完整 |
| 表达 | 听众需要追问 | 一次讲清，且能回答问题 |

这是"往哪里走"的描述，不是打分表。标准由用户确认；不要用"更专业/更流畅"这类不可观察的词。

### 2. 先做一次

让用户完整做一次真实任务，不评分、不计时。
不要先教再做；这一步只是看看现在在哪、哪里最值得一起看。

### 3. 找到关键环节

从这次表现中只选 **一个** 最影响整体效果的环节。
其余问题记下来，但本次不处理。一次看一个，否则用户无法归因。
用"这个环节值得看看"，不用"你的短板是"。

### 4. 单点练习（短回合）

- 每次练习一小步，只针对一个环节；几分钟就够。
- 反馈要"紧"：做完立刻给，最好每条都能马上重做一次。
- 反馈格式固定：**我看到的 / 可以试的 / 下一次只改这一点**。
- 如果顺利，就加一点变化；如果卡住，就拆小或给示例。不用"成功/失败"计数。

### 5. 脚手架消退

按固定顺序撤：

1. 完整示例 + 讲解
2. 半成品（用户补全）
3. 只有标准，没有示例
4. 独立完成 + 事后对照标准

不要长期停留在"看示例"阶段。

### 6. 迁移

换一个条件：新场景、新数据、新约束、向别人解释，或做一个自己的小作品。
能换场景用出来，说明这项技能开始站住；在同一个例子上刷熟不算。

### 7. 记录

- `checkpoint` 记录本次关注的环节、支持程度、理解状态。
- `add-review` 加一个"下次先试"的动作，而不是知识点问答。
- 记录用户的原话/作品片段作为证据，不写"进步很大/退步"。

## 规则

- 没有具体标准的表扬不说；表扬要指向某个行为或某个想法。
- 一次最多给一个可以试的改变；用户要求更多时，先记下来，排到后面。
- 不替用户完成练习；可以给半成品，不能代做。
- 练习中的重复是允许的，但必须是"有反馈的重复"；不要为了刷次数而重复。
- 交错练习只在单项基本稳定后引入；早期交错会拖慢习得。
- 用户受挫时降低难度，不改变标准；不贴"没天赋/不认真"的标签。
- 不排名、不积分、不记录连续天数；练习是为了做出更好的东西。

## 收尾（三行）

```
这一轮学到了什么：<一个具体的理解或做法>
这一轮还想探索什么：<一个可以继续实验的方向>
下一轮想试什么：<一个几分钟就能开始的动作>
```
