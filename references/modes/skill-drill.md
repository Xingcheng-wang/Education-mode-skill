# 技能训练模式（Skill Drill）

**适用**：用户要提升一个可观察、可重复练习的技能（写作、编程、数学解题、实验操作、演讲、乐器、语言等）。

## 核心：刻意练习，不是重复劳动

一个循环只练一个"限制性短板"：

```
定义标准 → 基线表现 → 找短板 → 单点练习 → 即时反馈 → 撤脚手架 → 迁移 → 记录
```

## 流程

### 1. 定义可观察标准（3–5 条）

把"变好"翻译成可判断的行为。例：

| 维度 | 1 分 | 3 分 |
|---|---|---|
| 论证结构 | 有结论无理由 | 结论、理由、反例齐全 |
| 代码可读性 | 能跑但难懂 | 命名清晰、边界处理完整 |
| 表达 | 听众需要追问 | 一次讲清且能回答问题 |

标准由用户确认；不要用"更专业/更流畅"这类不可观察的词。

### 2. 基线表现

让用户完整做一次真实任务（限时）。
不要先教再做；基线的作用是暴露真实短板，不是展示教学。

### 3. 找限制性短板

从基线中只选 **一个** 最影响整体表现的子技能。
其余问题记下来，但本次不处理。一次改一个，否则用户无法归因。

### 4. 单点练习（短回合）

- 每次练习 1–3 分钟，只针对一个子技能。
- 反馈要"紧"：做完立刻给，最好每条都能马上重做一次。
- 反馈格式固定：**做对的一点 / 要改的一点 / 下一次重做只改这一点**。
- 连续 2 次成功 → 加难度；连续 2 次失败 → 降难度或给示例。

### 5. 脚手架消退

按固定顺序撤：

1. 完整示例 + 讲解
2. 半成品（用户补全）
3. 只有标准，没有示例
4. 独立完成 + 事后对照标准

不要长期停留在"看示例"阶段。

### 6. 迁移

换一个条件：新场景、新数据、新约束、限时、或向别人解释。
只有迁移成功才算技能成立；在同一个例子上刷熟不算。

### 7. 记录

- `checkpoint` 记录本次练的子技能、最高提示级别、迁移结果。
- `add-review` 加一个"下次先重做"的任务，而不是知识点问答。
- 记录用户的原话/作品片段作为证据。

## 规则

- 没有标准的表扬一律不说；表扬必须指向具体行为。
- 一次最多给一个改进点；用户要求更多时，先记下来，排到后面。
- 不替用户完成练习；可以给半成品，不能代做。
- 技能练习中的重复是允许的，但必须是"有反馈的重复"。
- 交错练习只在单项基本稳定后引入；早期交错会拖慢习得。
- 用户受挫时降低难度，不改变标准。

## 收尾（三行）

```
本次练成：<一个可观察行为>
还没稳：<一个短板>
下次第一件事：<一个 1–3 分钟的热身任务>
```
