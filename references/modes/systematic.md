# 系统学习模式（Systematic）

**适用**：用户要从零或成体系地学一个主题，预期跨多次会话。

## 阶段

### 1. Mission（只做一次）

先聊清楚，写进 `learner/profile.md`：

- 什么让你好奇？你想解决什么问题？
- 学成之后想做出什么（具体场景，不是"想了解"）
- 现在的基础（用过什么、卡在哪）
- 每次能给多少时间（默认 20 分钟，不设 KPI）

Mission 模糊就先不建课程表；用 `curiosity` 模式先探索 1–2 次，再回来定。
不要把它写成"四周学完/每天打卡"的目标。

### 2. 资源准备

在诊断前先确认这个主题有哪些可用材料：

- `local` 模式：检查 `corpus/` 是否已有教材、论文、文档；不足就明确列出缺口，不要假装资料齐全。
- `web` 模式：搜集 3–5 个高质量来源（优先一手教材、官方文档、综述），缓存到 `corpus/` 并引用；查询只含主题关键词。
- 资源质量差或互相冲突：在主题图里标注，不要把冲突当成共识。
- 1M 上下文允许同时读多个来源，但只加载与当前节点相关的部分。

### 3. 诊断（3–5 个问题）

覆盖：前置概念、常见误解、能否迁移。
每题只问一个点；根据回答决定从哪个节点开始，不要假设"零基础"或"都学过"。

### 4. 问题地图（保持可理解）

先建一张最小可用的问题地图，不要一次规划几十个节点。格式：

| id | 主题 | 先修 | 为什么想学 |
|---|---|---|---|
| calculus/limits | 极限 | — | 想理解连续与逼近 |
| calculus/derivative | 导数 | calculus/limits | 想看懂变化率 |

规则：

- 每个节点尽量小，但允许在一个节点上多待一会儿；不要为了推进而推进。
- 先修关系只保留"不会它就学不动"的边，不要画知识全景图。
- 地图太大时，分成 2–3 个阶段，只展示当前阶段。
- 主题 id 用稳定的 `领域/主题` 形式，跨会话复用。

### 5. 每次会话

1. 如果用户问起，才列"可以重访的内容"；不主动催，不显示到期数量。
2. 选节点：与当前好奇相关即可；不按理解等级或"进度"筛选。
3. 如果自然，先请用户回忆上次/先修；不自然就直接讲，不为了"检索"而检索。
4. 微教学：一次只推进一个点；用户想多聊也可以。
5. 应用：邀请一个真实任务、一个小作品或一个例子；用户不想做时留作可选。
6. 迁移：换条件、场景或表示，邀请用户判断；不把它变成考试。
7. 记录：如果用户同意，`checkpoint` 只记概要；不默认写理解状态。`add-review` 只在用户要求时加。

### 6. 可能的方向（可选，不是门槛）

- 能复述 → 也许可以试着解释"为什么"。
- 能解释/应用 → 也许可以换一个场景或加一个边界问题。
- 能迁移/创造 → 也许可以去看更远的相关主题，或做一个真实项目。
- 暂时做不到 → 换一种讲法、拆小、或回到先修；不贴"基础差/不认真"的标签。
- 不设"必须达到某级才能继续"的门槛；用户的好奇比进度重要。

### 7. 可选重访

- 如果用户想，可以按 +1 天、+3 天、+7 天给一个建议日期；由用户决定是否采纳。
- 重访只做回顾和应用，不重新讲课；想不起来就回到微教学。
- 两次都没想起来 → 把节点拆小或回到先修，不催、不罚、不记"失败"。
- 复习是邀请，不是债务；错过不制造愧疚；用户可以把某条设为 `off`。

## 规则

- 不一次性输出整份课程大纲；每次只展示当前阶段和用户感兴趣的部分。
- 一次只推进一个点；用户想多聊也可以。
- 用户偏离计划时不催促；先问"你现在更想弄清楚什么"。
- 地图是导航，不是打卡清单；允许侧路、回头和跳过。
- 不显示完成率、覆盖率或"还剩几个节点"。
- 每次会话结束，如果用户愿意，更新主题图和可选的重访日期。
