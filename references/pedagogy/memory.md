# 记忆与练习机制

只使用有较强证据的机制；不使用学习风格、VAK、"左右脑"等说法。

## 0. 复习是邀请，不是债务

- 到期复习只是"可以再看看"的邀请，不是必须完成的任务。
- 不用"逾期/落后/坚持住"制造愧疚；错过了就下次再来。
- 不记录连续天数、不排名、不积分、不发徽章。
- 复习的第一目标是重新点燃理解，而不是"把卡片刷完"。
- 如果用户今天不想复习，尊重；可以换一个更好奇的问题。

## 1. 检索练习（Retrieval Practice）

- 先问后讲：新主题开始前，先让用户回忆相关旧知识。
- 复习时只给问题，不给答案；想不起来再给提示。
- 问题要"生成"而不是"再认"：不要选择题，优先"说出/写出/解释"。
- 需要时用；不要为了"完成检索"而把对话变成审讯。
- 用户正兴奋地探索时，不要打断去考他。

## 2. 间隔重复（Spaced Practice）

默认节奏（可按用户时间调整）：

| 阶段 | 下次复习 |
|---|---|
| 首次学 | +1 天 |
| 第二次成功 | +3 天 |
| 第三次成功 | +7 天 |
| 之后 | 按 SM-2 递增 |

- 复习失败：间隔回到 1 天，并降级到微教学。
- 不要求用户每天学；到期日按实际日期计算。
- 复习内容优先"为什么/怎么用"，而不是定义复述。

## 3. 交错练习（Interleaving）

- 只在单项基本稳定后使用。
- 把相近但不同的题型混在一起，让用户先判断"这是哪一类"。
- 新技能刚学时不要交错，会拖慢习得。

## 4. 合意难度（Desirable Difficulty）

- 如果太轻松、开始重复已知内容 → 换一个角度或加一个边界问题。
- 如果太挫败、连续卡住 → 降难度、拆步骤或换一个表示。
- 不用正确率数字设 KPI；观察用户的投入程度和理解质量。
- 允许犯错；错误要能被诊断，而不是被扣分。

## 5. 示例与消退（Worked Example → Fading）

1. 完整示例 + 讲解
2. 半成品：用户补关键一步
3. 只给标准，不给示例
4. 独立完成，事后对照

跳级会让用户卡住；长期停留会让用户产生"看懂了"的错觉。

## 6. SM-2 排程（脚本实现）

`scripts/edu.py` 使用简化 SM-2：

- 输入 0–5 的回顾结果；`grade < 3` 视为这次没想起来。
- 没想起来：`reps=0`、`interval=1`、`lapses+1`、`ease -= 0.2`（最低 1.3）。
- 想起来了：`reps+1`；间隔依次为 1、6、`round(interval * ease)`。
- `ease += 0.1 - (5-grade) * (0.08 + (5-grade) * 0.02)`，最低 1.3。
- 到期日 = 今天 + interval 天。

脚本只负责排程；grade 是内部调度信号，不是给用户的成绩。不要把 grade 展示给用户。

## 7. 复习题设计

好的复习题：

- "为什么 X 在 Y 条件下会失效？"
- "如果把这个参数改成 0，会发生什么？"
- "用一句话向初学者解释 X。"
- "给一个 X 的反例。"
- "这两道题看起来像，差别在哪？"

不好的复习题：

- "X 的定义是什么？"（可以背，不检验理解）
- "X 是 A 还是 B？"（再认，不是生成）
- 与上次完全相同的题（测的是记忆题目，不是知识）

## 8. 反模式

- 连续重读、划重点、抄笔记当作学习
- 一次学 3 小时，然后两周不碰
- 只在同一题型上刷熟
- 把"看懂了"当成"记住了"
- 用复习次数、打卡天数或连续记录衡量学习
- 用"逾期/落后"制造愧疚
- 为了清空复习队列而赶进度
- 把复习变成审讯，打断用户的好奇
