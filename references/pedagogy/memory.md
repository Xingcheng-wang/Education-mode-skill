# 记忆与练习机制

只使用有较强证据的机制；不使用学习风格、VAK、"左右脑"等说法。

## 1. 检索练习（Retrieval Practice）

- 先问后讲：新主题开始前，先让用户回忆相关旧知识。
- 复习时只给问题，不给答案；想不起来再给提示。
- 问题要"生成"而不是"再认"：不要选择题，优先"说出/写出/解释"。
- 一次会话至少 1 次检索，最多 3 次，避免变成审讯。

## 2. 间隔重复（Spaced Practice）

默认节奏（可按用户时间调整）：

| 阶段 | 下次复习 |
|---|---|
| 首次学 | +1 天 |
| 第二次成功 | +3 天 |
| 第三次成功 | +7 天 |
| 之后 | 按 SM-2 递增 |

- 复习失败：间隔回到 1 天，并降级到微教学。
- 不要求用户每天学；到期日按实际日期计算。
- 复习内容优先"为什么/怎么用"，而不是定义复述。

## 3. 交错练习（Interleaving）

- 只在单项基本稳定后使用。
- 把相近但不同的题型混在一起，让用户先判断"这是哪一类"。
- 新技能刚学时不要交错，会拖慢习得。

## 4. 合意难度（Desirable Difficulty）

- 正确率长期高于 90% → 加难度。
- 正确率低于 50% → 降难度或拆步骤。
- 目标区间大约 60%–80% 成功率；允许犯错，但错误要能被诊断。

## 5. 示例与消退（Worked Example → Fading）

1. 完整示例 + 讲解
2. 半成品：用户补关键一步
3. 只给标准，不给示例
4. 独立完成，事后对照

跳级会让用户卡住；长期停留会让用户产生"看懂了"的错觉。

## 6. SM-2 排程（脚本实现）

`scripts/edu.py` 使用简化 SM-2：

- 评分 0–5；`grade < 3` 视为失败。
- 失败：`reps=0`、`interval=1`、`lapses+1`、`ease -= 0.2`（最低 1.3）。
- 成功：`reps+1`；间隔依次为 1、6、`round(interval * ease)`。
- `ease += 0.1 - (5-grade) * (0.08 + (5-grade) * 0.02)`，最低 1.3。
- 到期日 = 今天 + interval 天。

脚本只负责排程；"这道题该不该算成功"由模型按评估规则判断，再传入 grade。

## 7. 复习题设计

好的复习题：

- "为什么 X 在 Y 条件下会失效？"
- "如果把这个参数改成 0，会发生什么？"
- "用一句话向初学者解释 X。"
- "给一个 X 的反例。"
- "这两道题看起来像，差别在哪？"

不好的复习题：

- "X 的定义是什么？"（可以背，不检验理解）
- "X 是 A 还是 B？"（再认，不是生成）
- 与上次完全相同的题（测的是记忆题目，不是知识）

## 8. 反模式

- 连续重读、划重点、抄笔记当作学习
- 一次学 3 小时，然后两周不碰
- 只在同一题型上刷熟
- 把"看懂了"当成"记住了"
- 用复习次数或打卡天数代替掌握度
