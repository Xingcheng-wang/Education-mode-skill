# 记忆与练习机制

只使用有较强证据的机制；不使用学习风格、VAK、"左右脑"等说法。

## 0. 复习由学习者发起

- 系统只保存"可以重访的内容"和一条建议日期，不主动催、不显示到期数量。
- 只有用户问起时，才列出可重访的条目；不把"今天有 5 个到期"当成待办。
- 不用"逾期/落后/坚持住"制造愧疚；错过了就下次再来。
- 不记录连续天数、不排名、不积分、不发徽章。
- 复习的第一目标是重新点燃理解，而不是"把卡片刷完"。
- 如果用户今天不想复习，尊重；可以换一个更好奇的问题。
- 用户可以把某条设为 `off`（暂停），系统不再列出。

## 1. 检索练习（Retrieval Practice）

- 先问后讲：新主题开始前，先让用户回忆相关旧知识。
- 复习时只给问题，不给答案；想不起来再给提示。
- 问题要"生成"而不是"再认"：不要选择题，优先"说出/写出/解释"。
- 需要时用；不要为了"完成检索"而把对话变成审讯。
- 用户正兴奋地探索时，不要打断去考他。

## 2. 间隔重复（Spaced Practice）

建议节奏，不是任务表：

| 阶段 | 可以重访的时间 |
|---|---|
| 首次学 | +1 天 |
| 第二次想起来 | +3 天 |
| 第三次想起来 | +7 天 |
| 之后 | 按 SM-2 给建议 |

- 没想起来：回到更小的单元，不记"失败"；下次可以早点或晚点，由学习者决定。
- 不要求用户每天学；建议日期只是参考。
- 复习内容优先"为什么/怎么用"，而不是定义复述。
- 用户可以随时把某条设为 `off`，不解释也可以。

## 3. 交错练习（Interleaving）

- 只在单项基本稳定后使用。
- 把相近但不同的题型混在一起，让用户先判断"这是哪一类"。
- 新技能刚学时不要交错，会拖慢习得。

## 4. 合意难度（Desirable Difficulty）

- 如果太轻松、开始重复已知内容 → 换一个角度或加一个边界问题。
- 如果太挫败、连续卡住 → 降难度、拆步骤或换一个表示。
- 不用正确率数字设 KPI；观察用户的投入程度和理解质量。
- 允许犯错；错误要能被诊断，而不是被扣分。

## 5. 示例与消退（Worked Example → Fading）

1. 完整示例 + 讲解
2. 半成品：用户补关键一步
3. 只给标准，不给示例
4. 独立完成，事后对照

跳级会让用户卡住；长期停留会让用户产生"看懂了"的错觉。

## 6. 建议排程（脚本实现）

`scripts/edu.py` 保留简化 SM-2 作为**建议**，不是任务队列：

- 用户可以用 `revisit --item-id r0001 --next 3d|7d|off|YYYY-MM-DD` 自己选。
- `off` 表示暂停，系统不再列出，也不提醒。
- 只有用户要求"给个建议"时，才用 `--grade` 让 SM-2 算一个日期；输出只说"下次建议"，不打印 grade/interval/lapses。
- `due` 是建议日期，不是到期债务；`reviews` 只在用户问起时列出。
- grade 是内部调度信号，不是给用户的成绩；永远不展示给用户。

## 7. 重访问题设计

好的重访问题：

- "为什么 X 在 Y 条件下会失效？"
- "如果把这个参数改成 0，会发生什么？"
- "用一句话向初学者解释 X。"
- "给一个 X 的反例。"
- "这两道题看起来像，差别在哪？"

不好的重访问题：

- "X 的定义是什么？"（可以背，不检验理解）
- "X 是 A 还是 B？"（再认，不是生成）
- 与上次完全相同的题（测的是记忆题目，不是知识）

## 8. 反模式

- 连续重读、划重点、抄笔记当作学习
- 一次学 3 小时，然后两周不碰
- 只在同一题型上刷熟
- 把"看懂了"当成"记住了"
- 用复习次数、打卡天数或连续记录衡量学习
- 用"逾期/落后"制造愧疚
- 为了清空复习队列而赶进度
- 把复习变成审讯，打断用户的好奇
- 在 `status` 里显示到期数量、grade、lapses
- 用户没问就主动催"该复习了"
