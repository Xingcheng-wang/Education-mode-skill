# 兴趣：入口、燃料、关系

兴趣不是学习的装饰，也不是“把课讲得好笑”。
兴趣是人和内容之间的一种关系，需要设计、读人、维护。

## 1. 两种兴趣

- **情境兴趣**：由某个情境、故事、意外、挑战、动手活动触发；短暂，但能打开门。
- **个人兴趣**：与学习者的长期目标、身份、价值相连；更稳，但需要时间。

好的教学先用情境兴趣打开门，再慢慢接到个人兴趣上。

## 2. 兴趣的来源

- **意义**：为什么值得做？它和服务于什么？
- **选择**：做什么、怎么做、先做哪一步、做到什么程度。
- **可见结果**：能看到、能用到、能给别人看。
- **故事**：一个人、一个冲突、一个“为什么会这样”。
- **悬念/意外**：先猜，再揭示；让结果和直觉打架。
- **审美**：优雅的代码、漂亮的图、好的文字、干净的设计。
- **挑战**：略高于当前能力，但不威胁。
- **关系**：被看见、被尊重、犯错安全、有人一起。
- **进度**：不是完成率，而是“我现在能做什么了”。

## 3. 兴趣的信号

- 主动追问；
- 回到之前的问题；
- 自己开始试/改；
- 眼睛亮了一下（文字上：语气变长、感叹、具体化）；
- 不想停；
- 开始教别人/解释给别人听。

反面信号：

- 只回“嗯/好/继续”；
- 频繁换话题；
- 只问“这个考不考”；
- 回避动手；
- 疲劳、烦躁、沉默。

## 4. 兴趣设计的招式

- 从用户想要的结果开始，不从定义开始。
- 给 2–3 个不同风味的入口，让用户选。
- 先做一个最小可见实验，让结果发生。
- 把内容和用户已经在意的东西连起来。
- 用故事/冲突/反例制造“想知道”。
- 让用户自己做一个小决定（节奏、风格、约束）。
- 给真实约束，不要玩具题。
- 让结果可以被看见/使用/展示。
- 在用户兴奋时跟随，不要用“先把这章学完”打断。

## 5. 兴趣不是游戏化

- 积分、徽章、排行榜是外部奖励，可能挤出内在兴趣。
- 游戏化可以是入口，但不能替代意义、选择和可见结果。
- 不要用“好玩”掩盖“没讲清楚”。
- 不要用兴趣操纵用户；用户可以拒绝、可以停。

## 6. 兴趣与难度

- 太简单 → 无聊；太难 → 焦虑。
- 目标：挑战略高于当前能力，但有支持。
- 用户卡住时，先降难度/换表示，不要用“再坚持一下”。
- 用户无聊时，加挑战/换入口/连接目标，不要加更多重复。

## 7. 兴趣与身份

- 用户可能不认为自己是“数学人/编程人/研究者”。
- 不要强化这种标签；让他先做出一个结果，再让身份自己长出来。
- 用“你现在能做 X 了”而不是“你很有天赋”。

## 8. 例子

FPGA：

- 不问“写出 blink 模块外壳”；
- 问“你想让 LED 怎么亮？心跳、摩斯、按钮？”
- 先让 LED 常亮，看到结果；
- 再让节奏变化；
- 理论在需要时出现：时钟、计数器、module、port。

LLM 记忆：

- 不问“写一个记忆协议”；
- 问“你希望换一个模型时，哪些记忆能带走？”
- 先做一个小实验：从一个系统导出、导入另一个，看看丢什么；
- 理论在需要时出现：schema、provenance、forget、permission。
