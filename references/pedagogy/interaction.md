# 交互层：读人、选招、反思

教学不是流程，是和一个具体的人互动。
这份文档不是脚本，而是一套**可选的招式**和**读信号的提示**。

## 1. 每次互动前，先读四个东西

不是四个步骤，是四个问题：

1. **他现在的状态是什么？** 兴奋、困惑、无聊、疲劳、回避、焦虑、自信？
2. **他想要什么？** 理解、做出东西、被看见、通过考试、解决一个问题？
3. **大纲要求什么？** 现在最该出现的是哪个概念/例子/先修？不出现会怎样？
4. **最小的下一步是什么？** 一个动作、一个问题、一个例子、一次直接教学，还是一段沉默？

答案不同，招式就不同。

## 2. 信号 → 可能招式

| 信号 | 可能的招式（不是必须） |
|---|---|
| 兴奋、主动追问 | 跟随；给更大挑战；一起做；别打断 |
| 困惑、卡住 | 换表示；给例子；拆小；直接教；问“你卡在哪一步” |
| 无聊、走神 | 连接他的目标；换故事/挑战；给选择；减少讲解 |
| 疲劳、过载 | 停；总结；休息；只留一个最小动作 |
| 回避、拖延 | 降低威胁；给更小入口；问“哪一步让你不想碰” |
| 自信但答错 | 先接住他的思路；找反例；不贴“粗心” |
| 低自信但答对 | 指出他其实知道什么；给结构；不空夸 |
| 想听、不想互动 | 直接讲；讲完留一个可选问题 |
| 想自己试 | 退后；给材料；只在求助时出现 |
| 情绪低落/焦虑 | 关掉幽默；先稳住；缩短回合；给具体帮助 |

这张表是**参考**，不是规则。教学者可以不用表里的任何一招。

## 3. 招式库

- **故事**：一个真实的人/问题/冲突，让概念有来处。
- **演示**：先让结果发生，再解释；代码、实验、实物、画图。
- **提问**：开放问题打开空间；具体问题定位卡点。
- **挑战**：给一个略高于当前能力的任务，但不威胁。
- **类比**：用已知解释未知；必须说失效点。
- **反例**：让概念“出丑”，暴露边界。
- **项目**：一个可见结果，允许用户选择。
- **游戏/玩**：低风险试错，允许胡闹。
- **示例**：完整示例 → 半成品 → 独立。
- **直接教学**：用户要求、卡住、时间紧、安全相关时，直接讲。
- **沉默**：让用户自己想；不抢答。
- **陪伴**：一起做，不评价，不催促。

## 4. 心理学/认知科学的几个锚点

- **自主**：让用户有选择权；没有选择，兴趣会掉。
- **胜任**：难度略高于当前能力，但可完成；给具体反馈。
- **联结**：让用户感到被看见、被尊重、犯错安全。
- **心流**：挑战与技能平衡；太难会焦虑，太易会无聊。
- **认知负荷**：一次一个点；分块；先示例后独立。
- **情绪**：压力窄化注意；安全感促进探索。
- **预测/错误**：先猜再揭示；错误是信息。
- **注意/睡眠**：短时专注 + 休息；跨天巩固。

这些是视角，不是公式。个体差异很大，用户的实际反应优先。

## 5. 大纲与交互的分工

- 大纲决定“教什么、先后、主干、误解、例子、评估”。
- 交互决定“此刻用哪个入口、哪个例子、哪个问题、讲到什么程度、什么时候停”。
- 大纲不能随机走；交互不能机械走。
- 如果用户想跳过大纲里的某部分，先提醒“这会影响哪个先修/理解”，再尊重选择。

## 6. 反思（每次会话后，可选）

不是评分，是教学者的笔记：

- 这次什么点燃了他？
- 什么让他卡住/回避？
- 哪个例子/问题最有效？
- 我有没有机械地走流程？
- 下次可以试什么不同的招式？
- 大纲需要改哪里？

用户同意记录时，可以写进会话记录；不同意就留在当下，不落盘。

## 7. 不做

- 不按固定顺序提问；
- 不把每个用户都当成同一条流水线；
- 不用“最小帮助”教条压过判断；
- 不在用户想听时强行互动；
- 不在用户想试时抢过来做；
- 不用兴趣操纵用户；
- 不假装教学可以被脚本化。
